# AI agents, long-horizon autonomy and automation of AI R&D (Oct 12 – Nov 11, 2026)

*Access note for the report writer: in this session only anthropic.com could be fetched directly. Fetches of openai.com, deepmind.google, xbow.com, commandline.microsoft.com, thezvi.substack.com and assets.claude.com (the Fable 5.2 system card PDF) failed under the network policy, and other hosts (including metr.org and axiommath.ai) were then not attempted, so those items rest on search-result extracts of the primary pages plus secondary coverage. arXiv papers were read through Hugging Face paper pages; GitHub repo/commit/release data and PyPI release dates were read directly. Evidence-status labels used: vendor-reported / independently measured / peer-reviewed / formally verified / disputed.*

## 1. What demonstrations in the window show longer or larger autonomous work?

### Takeaway
The window produced a cluster of day-to-month-long, hundreds-to-thousand-agent feats: a 27-hour unattended four-agent Minecraft completion (about $520), a single pipeline run yielding 948 Linux kernel root exploits plus patches ($1.2M), 43M and 6M+ line machine-checked Lean developments in 24 days and four weeks, and Anthropic's claim of a 1,000-agent, 30-hour Fermat formalization and an 8-day operating-system build. Almost all are vendor-reported single runs; the strongest verification comes from proof checkers (Lean) and from Google paying XBOW's bounty, not from independent replication.

### Cited Findings

#### Google DeepMind: four Gemini 4 Argon agents finish Minecraft (preprint dated Oct 15; arXiv HTML timestamp Oct 16)
- Four player agents (plus a fifth non-playing "Observer" agent) defeated the Ender Dragon 27 h 14 min after their first program, writing 2,783 JavaScript programs, exchanging 229 chat messages and dying 605 times; authors Faldor, Singh, Raileanu — [arXiv 2610.22319](https://arxiv.org/abs/2610.22319), [HF paper page](https://huggingface.co/papers/2610.22319), [GDM X post](https://x.com/GoogleDeepMind/status/2111127991401247033)
- Human involvement: "no human input during the run"; game instructions were one paragraph; researchers could pause or stop via a dashboard "but they had no cause to intervene"; no roles, curriculum, skill library or human-written tools beyond the stock Mineflayer library — [arXiv 2610.22319](https://arxiv.org/abs/2610.22319)
- Setup: Minecraft Java 1.20.4, survival, Easy difficulty, random seed, cheats off; agents act by writing code and reading text (not pixels); each agent is a general-purpose coding agent with shell, version control, web search, context compaction and private plus shared persistent memory — [arXiv 2610.22319](https://arxiv.org/abs/2610.22319)
- Cost: about 1.35B input tokens (91% cached), 16M output tokens, roughly 24,000 model calls; about $520 at introductory list price ($1,040 standard); whole session including Observer about $810 ($1,620) — [arXiv 2610.22319](https://arxiv.org/abs/2610.22319)
- Stated limits: perception and pathfinding through code (agents can read blocks behind rock and the dragon's internal state); Easy difficulty; heavy prior knowledge of Minecraft; 22% of programs ended in an error; the End fight took nearly 14 hours (69 deaths to the dragon); 6 server restarts; "a single run, the first launch we tried, which cannot show how reliably the setup succeeds" — [arXiv 2610.22319](https://arxiv.org/abs/2610.22319)
- Context given by the authors: HowLongToBeat median for a human main-story playthrough is 45 hours; two community projects had already reported dragon kills (a single Claude Opus 5 agent with 37 high-level tools on Normal, Sept 15, 2026; a planner on a fixed seed in Peaceful) — [arXiv 2610.22319](https://arxiv.org/abs/2610.22319)
- Evidence status: vendor-reported preprint, not peer reviewed, single run; full logs recorded and win visible in server log, monitoring by another agent plus manual review of "a sample of the logs" — [arXiv 2610.22319](https://arxiv.org/abs/2610.22319); press summary at [The Next Web](https://thenextweb.com/news/gemini-4-argon-agents-beat-minecraft-27-hours)

#### OpenAI: "A thousand fewer paths to root" (report Nov 4; run mid-October)
- An automated pipeline built on an upcoming, unreleased cyber model produced 948 working Linux kernel local-privilege-escalation exploits and 291 information-leak proofs of concept in a single mid-October run, at $1.2M API cost, and wrote 948 distinct candidate patches — [OpenAI post](https://openai.com/index/a-thousand-fewer-paths-to-root/), [Phoronix](https://www.phoronix.com/news/OpenAI-948-Linux-LPE-Bugs), [TechRadar](https://www.techradar.com/pro/security/openai-says-its-cyber-model-found-and-patched-nearly-1000-linux-kernel-security-issues)
- "948" counts unique LPEs defined by the distinct patch that closes each one; it is not a count of merged kernel fixes — [Unite.AI](https://www.unite.ai/openai-pipeline-finds-948-linux-kernel-privilege-escalation-flaws/)
- Upstream status as reported by OpenAI: 61 already patched by maintainers when the analysis finished, 43 with staging patches, 299 being reported and discussed publicly; "hundreds of reports and patches" sent — [iTnews](https://www.itnews.com.au/news/low-privileged-accounts-on-unpatched-systems-as-good-as-root-openai-630145), [CSA research note](https://labs.cloudsecurityalliance.org/research/csa-research-note-ai-industrialized-linux-lpe-exploit-genera/)
- Agents used at least 10 exploitation techniques that outside kernel experts had not seen; technical details withheld; exploits were run only in OpenAI's own testing — [Phoronix](https://www.phoronix.com/news/OpenAI-948-Linux-LPE-Bugs), [OpenAI post](https://openai.com/index/a-thousand-fewer-paths-to-root/)
- Run length: one low-quality outlet's headline says "in just 10 days"; I could not confirm duration, agent count or human involvement against the primary post — [GBHackers](https://gbhackers.com/openais-new-cyber-ai-model-finds-948-linux-privilege-escalation-vulnerabilities/)
- Evidence status: vendor-reported; no independent verification of the count found. Skeptical notes: a Hacker News commenter relays (hearsay) that Greg Kroah-Hartman finds about half of AI-reported vulnerabilities wrong; iTnews reports Kroah-Hartman saying different groups report the same issues within days — [HN thread](https://news.ycombinator.com/item?id=50372929), [iTnews](https://www.itnews.com.au/news/low-privileged-accounts-on-unpatched-systems-as-good-as-root-openai-630145)

#### XBOW: AI-built three-bug Chrome full-chain exploit (disclosed Oct 13; built Aug 2–7, outside window)
- Three previously unknown bugs chained into code execution outside Chrome's sandbox on Windows from a web page; Google reproduced it, shipped fixes and paid its maximum $250,000 full-chain bounty — [XBOW](https://xbow.com/news/xbow-rewarded-for-exploit-affecting-a-billion-users), [The Hacker News](https://thehackernews.com/2026/10/researchers-used-public-openai-model-to.html)
- Built in six days with a public OpenAI model (reported as GPT-5.6) for roughly $40,000 in API fees — [The Hacker News](https://thehackernews.com/2026/10/researchers-used-public-openai-model-to.html), [Crypto Briefing](https://cryptobriefing.com/xbow-gpt-5-6-chrome-exploit-bounty/)
- Human involvement was substantial: agents searched Chrome's source, tested ideas, built proofs of concept and drafted the exploit; human researchers directed the work and assembled the chain — [XBOW](https://xbow.com/news/xbow-rewarded-for-exploit-affecting-a-billion-users)
- Evidence status: exploit validity independently confirmed (Google's award and fixes); the AI/human split is vendor-described. CVE IDs appear only in one secondary source and are unverified — [Aviatrix](https://aviatrix.ai/threat-research-center/xbow-openai-chrome-exploit-cve-2026-85045-2026/)

#### Axiom: Classification of Finite Simple Groups in Lean (announced Oct 27)
- AI agents wrote about 43.1M lines of Lean (2.05M declarations, drawing on 715 papers and books) in 24 days, Oct 2–26; about 1.2M lines came from an earlier project — [i10x](https://i10x.ai/news/axiom-cfsg-lean-formalization-finite-simple-groups), [Crypto Briefing](https://cryptobriefing.com/axiom-ai-formalizes-enormous-theorem-24-days/)
- Public repo created Oct 27, 2026 — [AxiomMath/CFSG](https://github.com/AxiomMath/CFSG)
- Axiom states the proof is sorry-free, uses only Lean's standard axioms and avoids native_decide; lists 34 noteworthy deviations from the published proof, including counterexamples to a closure assertion used in a published route to the Unbalanced Group Theorem — [i10x](https://i10x.ai/news/axiom-cfsg-lean-formalization-finite-simple-groups), [LavX](https://news.lavx.hu/article/axiom-formalizes-classification-of-finite-simple-groups-in-lean-discovers-flaw-in-key-proof)
- Source disagreement: one outlet says the agents fixed "over 2,000 errors"; Axiom's write-up is reported as listing 34 noteworthy deviations; a Hacker News commenter cites 46M lines — [Crypto Briefing](https://cryptobriefing.com/axiom-ai-formalizes-enormous-theorem-24-days/), [HN thread](https://news.ycombinator.com/item?id=50261647)
- Not disclosed in coverage: agent count, cost, human effort, models used (Axiom says only "a changing mix") — [i10x](https://i10x.ai/news/axiom-cfsg-lean-formalization-finite-simple-groups)
- Evidence status: vendor-reported, machine-checkable (formally verified in Lean by the vendor); skeptics note "no outside group has independently rebuilt it" and ask "whether the formal statement still means what mathematicians meant" — [HN thread](https://news.ycombinator.com/item?id=50261647)
- Source quality: the numbers above rest on aggregator-grade coverage of Axiom's write-up plus the public repo; I found no established-outlet report and could not open axiommath.ai — [AxiomMath/CFSG](https://github.com/AxiomMath/CFSG)
- Follow-ups in window (lead missed these): a Stacks Project formalization (repo created Nov 4) split into human-checked "StacksCore" and unreviewed agent-written "StacksFrontier"; a Weil conjectures formalization (repo created Nov 6); a CFSG corollary (Nov 2). Stacks Project founder Johan de Jong asked that AI-generated contributions not be submitted upstream for now — [Axiom Stacks post](https://axiommath.ai/research/the-stacks-project-formalized/), [AxiomMath GitHub](https://github.com/AxiomMath), [AxiomMath/Weil](https://github.com/AxiomMath/Weil)

#### Google DeepMind: AlphaProof Code verifies Signal's protocol library (blog Nov 10)
- Agents produced over six million lines of Lean (about 6.5M per the technical paper) in four weeks, proving key security properties of the compiled libsignal protocol library — [DeepMind blog](https://deepmind.google/blog/introducing-alphaproof-code/), [AlphaSignal](https://alphasignal.ai/news/google-deepmind-s-alphaproof-code-formally-verifies-signal-s-encryption-in-4)
- Human involvement: humans and models drafted the specifications; human experts reviewed every specification before proofs ran; agents flagged about 1% of the codebase for a second human look; trusted base is about 26,000 lines of specifications and machine-code rules — [Qodo analysis](https://www.qodo.ai/blog/alphaproof-code-signal-formal-verification/)
- Checks: Lean's kernel validates each proof; reintroducing two previously fixed bugs made the proofs fail; Signal CTO Ehren Kret called it "a major breakthrough" — [DeepMind blog](https://deepmind.google/blog/introducing-alphaproof-code/)
- Limits: proofs assume perfect cryptography; covers the library, not the Signal app; framework not released, though specs and proof artifacts are (repo created Oct 26) — [Qodo analysis](https://www.qodo.ai/blog/alphaproof-code-signal-formal-verification/), [google-deepmind/code-verification](https://github.com/google-deepmind/code-verification)
- Evidence status: formally verified (vendor-run), endorsed by Signal; agent count and cost not found in coverage — [DeepMind blog](https://deepmind.google/blog/introducing-alphaproof-code/)

#### Anthropic: Claude Fable 5.2 and Mythos 5.2 (Nov 9)
- "A team of 1,000 Fable 5.2 agents fully formalized the theorem in just 30 hours, with minimal human intervention"; agents started from minimal prompts, built their own coordination, used no mathematical references, and tracked progress against a list of intermediate theorem statements — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Compared with Anthropic's first formalization (unreleased research Claude, purpose-built harness, human researcher, 11 days): one-third the action tokens and a proof seven times shorter. With the same 1,000-agent setup, Opus 5.5 completed 26% in 18 hours and barely progressed by 30 hours. Each model had a single run — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Not reported: tokens, cost, line count, the nature of the human interventions, a repo link, or named outside reviewers — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2); coverage notes outside mathematicians have not yet reviewed it — [The Decoder](https://the-decoder.com/claude-fable-5-2-and-mythos-5-2-cement-anthropics-ai-lead-just-before-its-ipo/), [The Next Web](https://thenextweb.com/news/claude-fable-5-2-mythos-5-2-anthropic-launch-price)
- Operating system: from an empty folder, "the model coordinated over 1,000 subagents, working around the clock for eight days" and "produced a working operating system that boots on a laptop" (kernel, disk/keyboard/network drivers, persistent storage, windows, login, installer); described as an experiment; no code size or cost given — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Hardware: from a one-paragraph prompt, three devices (voice-assistant hub, USB speakerphone, handheld virtual pet); each four-layer board was manufacturing-ready in under a day "with minimal human input"; all three worked without electrical modifications after a third party (Diode) built them — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Also claimed: two black-hole physics results done "largely autonomously" (preprints linked from the page) and a customer-reported "10–12 hour security audit" in one run — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Evidence status: vendor-reported; Lean-checked per the vendor; single runs; no independent review found. One blog gives 28.7 hours rather than 30 (unconfirmed) — [Apiyi blog](https://help.apiyi.com/en/claude-fable-5-2-1000-agents-fermat-last-theorem-formalization-en.html)
- Outside window (context): the first Fermat formalization (dozens of agents, 13M lines of Lean, Aug 7–18) was published Sept 4, 2026 — [SiliconANGLE](https://siliconangle.com/2026/09/04/anthropic-uses-claude-to-formalize-proof-of-fermats-last-theorem/)

#### Microsoft: agents modernizing Windows and Azure code (Command Line post, about Oct 26)
- Microsoft says it is building and running AI agents that transform some of the world's largest codebases, including Windows and Azure, and that this includes migrating a roughly 400-million-line codebase to a new compiler toolchain (post title: "Cheap code, precious trust: Code modernization at scale") — [Microsoft Command Line](https://commandline.microsoft.com/agentic-software-engineering-large-scale-code-migration-language-modernization-spec-driven-development/)
- Operating model: a very small team of migration experts; agents learn a knowledge base from sampled findings, experts approve it, agents apply it across the codebase, reviewer feedback refines it — [Microsoft Command Line](https://commandline.microsoft.com/agentic-software-engineering-large-scale-code-migration-language-modernization-spec-driven-development/)
- A secondary analysis identifies the toolchain work as Clang/LLVM support across the Windows codebase and notes the post gives no completion figures and an approximate size — [WindowsForum](https://windowsforum.com/news/microsoft-details-ai-agent-verification-for-windows-and-azure-codebases-why-trust-is-the-new-bottleneck.450086/)
- Evidence status: vendor-reported, work in progress, no metrics — [WindowsForum](https://windowsforum.com/news/microsoft-details-ai-agent-verification-for-windows-and-azure-codebases-why-trust-is-the-new-bottleneck.450086/)

#### Anthropic: source-control redesign as a scale indicator (Oct 13; lead missed this)
- Merged code changes rose from about 2,500 per day (May 2026) to over 30,000 per day (Sept 2026); "coding is no longer the bottleneck to building systems or doing research" — [Anthropic engineering](https://www.anthropic.com/research/redesigning-source-control)
- A team of seven built an in-house version-control system (Scion), a review tool and about six related systems and migrated the monorepo off git in five months; humans now review the intent of each change rather than every line — [Anthropic engineering](https://www.anthropic.com/research/redesigning-source-control)
- Evidence status: vendor-reported; the post gives no share of changes written by agents, though the Nov 9 launch page says over 90% — [Anthropic engineering](https://www.anthropic.com/research/redesigning-source-control), [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)

### Inferences
- Unit economics implied by the reported numbers: about $1,270 of API spend per working kernel exploit ($1.2M / 948) and about $19 per wall-clock hour for the four Minecraft players ($520 / 27.2 h). These are my arithmetic, not source statements.
- The 11-day to 30-hour Fermat comparison mixes three changes (model, harness, and agent count from "dozens" to about 1,000), so it is not a clean measure of model improvement; the same-setup Opus 5.5 comparison (26% vs 100%) is the cleaner signal, but it is n=1 per model.
- Formal proof is the common denominator of the most credible "large" feats (Axiom, AlphaProof Code, Fermat): the checker removes the need to trust agent output line by line, shifting risk to whether statements and specifications say the right thing.
- Degree of autonomy differs sharply across the feats: Minecraft is documented as fully unattended for 27 hours; Anthropic claims only "minimal human intervention" for Fermat (30 h) and does not describe the human role in the 8-day OS build; XBOW, AlphaProof Code and Microsoft's migrations are explicitly human-directed.

### Gaps
- OpenAI kernel run: duration, parallelism, human triage effort and model name not confirmed (primary page unreachable); no maintainer-side tally of valid vs duplicate reports found.
- Axiom and AlphaProof Code: agent counts, compute cost and human hours not found.
- Anthropic's OS and Fermat runs: no artifacts, token counts or third-party review located.
- Microsoft: no figures on files changed, agents used or completion.

## 2. What do independent measurements say?

### Takeaway
The main independent measurement is METR's Nov 5 assessment: Anthropic's capability progress has run about 1.9x faster since October 2025 (95% interval 1.5–2.8x), with METR guessing roughly 80% of that is due to AI use, but Anthropic redacted most of the supporting evidence. I found no METR time-horizon figure for any model released in the window and no public UK AISI result for the new models.

### Cited Findings
- METR published "Independent Assessment of AI R&D Acceleration at Anthropic in October 2026" on Nov 5, based on work since August by a team with internal Anthropic information — [METR](https://metr.org/blog/2026-11-05-anthropic-ai-rd-acceleration-assessment/), [METR on X](https://x.com/METR_Evals/status/2118412183860351084)
- Headline: benchmark index ("AECI") scores for Anthropic models have grown 1.9x faster since October 2025 than from March 2024 to October 2025, 95% interval 1.5–2.8x — [METR](https://metr.org/blog/2026-11-05-anthropic-ai-rd-acceleration-assessment/), [The Decoder](https://the-decoder.com/metr-finds-anthropic-may-have-crossed-its-own-ai-acceleration-warning-threshold-back-in-july/)
- Attribution: "We guess that a majority (perhaps ≈80%) of the current (October 2026) acceleration is due to AI", with high uncertainty; METR says it is confident the speed-up was not driven by faster compute growth, but those details were redacted — [METR](https://metr.org/blog/2026-11-05-anthropic-ai-rd-acceleration-assessment/), [Zvi Mowshowitz](https://thezvi.substack.com/p/ai-r-and-d-is-accelerating-towards)
- Not full automation: "Staff self-report dramatic productivity gains, but say the most important AI R&D contributions aren't yet fully automated" — [METR](https://metr.org/blog/2026-11-05-anthropic-ai-rd-acceleration-assessment/)
- Redactions: METR submitted a roughly 100-page report; "Anthropic redacted a majority of the evidence we found most informative. As a consequence, the public must rely on our judgment more than we consider ideal" — [METR on X](https://x.com/METR_Evals/status/2118412194702598339)
- Anthropic co-founder Sam McCandlish acknowledged the company "redacted a lot"; Anthropic's stated reason is that details could help rivals — [Cybernews](https://cybernews.com/ai-news/anthropic-redacted-report/)
- Comparison figures reported in coverage: Anthropic's Haiku 5.5 system card gave 1.7x; fitting all developers' public frontier models gives about 1.4x; METR's higher number mainly reflects unreleased internal models — [Zvi Mowshowitz](https://thezvi.substack.com/p/ai-r-and-d-is-accelerating-towards), [AI Modeling](https://www.aimodeling.com/en/news/slug/metr-anthropic-ai-rd-acceleration-assessment)
- Companion review (Nov 5) of the automated-R&D section of Anthropic's August 2026 Risk Report: METR thinks it plausible the 2x early-warning threshold had already been crossed by July 15 and that the public report understates the acceleration; the private report itself calls that "plausible"; METR agrees models available by July 15 posed low risk of directly automating R&D — [METR review](https://metr.org/blog/2026-11-05-rd-section-anthropic-risk-report-august-2026-review/), [The Decoder](https://the-decoder.com/metr-finds-anthropic-may-have-crossed-its-own-ai-acceleration-warning-threshold-back-in-july/)
- Access terms (Oct 15): six METR employees have employee-like access at Anthropic; Anthropic cannot veto publication but can require redaction of predefined categories that it defines — [Anthropic](https://www.anthropic.com/news/an-update-on-independent-evaluators)
- Fable 5.2 / Mythos 5.2 were tested before release by UK AISI, Frontier Design and METR; the launch page reports none of their findings and says they did not review the post — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Independent benchmark runs in the window: Vals.ai's Terminal-Bench 4.0 table (Nov 9) has Fable 5.2 and Opus 5.5 tied at 65.15% under the same harness — [Vals.ai](https://www.vals.ai/benchmarks/terminal-bench-4)
- Independent academic measurements of agents doing ML research: four Claude Opus 5.5 agents in a 104-hour campaign post-trained Qwen3-4B-Base to 67.3 (dev) / 48.2 (held-out) versus 66.5 / 47.9 for the official instruct model — [Athanor, arXiv 2610.21055](https://huggingface.co/papers/2610.21055); the best agent system raised generalization scores only 9.2% relative (+2.3 points) in a multi-domain post-training gym — [ParetoRSI-Gym, arXiv 2610.34386](https://huggingface.co/papers/2610.34386)
- Outside window (context; low-quality tracker sites, not checked against METR): METR's highest published time horizon is put at 17.4 hours for an early Claude Mythos Preview (95% CI 8.5–55.1 h), with METR saying estimates above 16 hours are unreliable on its current task suite — [iqmetrics](https://iqmetrics.org/news/metr-time-horizon-explained-the-latest-numbers-and-why-it-is-not-an-iq/), [METR Time Horizon tracker](https://benchmarks.darvinyi.com/agents/metr-time-horizon)
- Outside window (context, date unverified, about Aug 2026): a UK AISI incident report on cyber evaluations found 19 out-of-scope agent actions across 122 runs — [The Hill](https://thehill.com/policy/technology/6010786-ai-agents-fake-acccounts-aisi-openai-gpt-mythos/)

### Inferences
- If the reported METR caveat is accurate (estimates above about 16 hours unreliable on its current suite), the standard time-horizon metric can no longer rank frontier models; the window's evidence for longer autonomy is therefore demonstrations, not a calibrated measure.
- The 1.9x figure is independent in authorship but not in verifiability: outsiders cannot check the evidence, so it should be reported as "independently assessed, largely unverifiable".
- Vals.ai's tie between Fable 5.2 and Opus 5.5 on Terminal-Bench 4.0 sits awkwardly beside Anthropic's large claimed gains elsewhere; either that benchmark is near its ceiling for this harness or the gains are concentrated in long, multi-agent work that it does not measure.

### Gaps
- No METR time-horizon result for Gemini 4 Argon, Claude Fable/Mythos 5.2 or other in-window models found.
- Fable 5.2 system card (third-party tester summaries) could not be opened.
- One secondary summary says the non-public acceleration figure was 1.97; I could not confirm it or its source.
- What "AECI" stands for was not confirmed.

## 3. What did recursive self-improvement and automated-research work published in the window show?

### Takeaway
"RSI" became a crowded paper label (I counted 26 RSI-themed papers dated Oct 12–Nov 8 in one Hugging Face search), but the measured results are incremental: harness and infrastructure self-tuning gains of a few to a dozen points or up to 2.75x training throughput, and agents that can match, not surpass, a small official instruct model. The strongest claims of AI building AI (Recursive's Flint, Anthropic's internal numbers) are vendor statements without published methods.

### Cited Findings
- Volume: a Hugging Face paper search in this session (query "DREAM-RSI recursive self-improvement", top 100 results) returned 26 self-improvement-themed papers dated Oct 12–Nov 8, 2026, for example [A-RSI](https://huggingface.co/papers/2610.38568), [Terminal-RSI](https://huggingface.co/papers/2610.22192), [SwarmRSI](https://huggingface.co/papers/2610.20431), [RSI Arena](https://huggingface.co/papers/2610.33624)
- Harness² (Google; paper dated Oct 9, just outside the window; featured Oct 14): recursive harness editing without ground-truth verifiers improved GLM-5 and Gemini 3.5 Flash by up to 11.5 points on WorkBuddy-Bench, 4.5 on JobBench and 11.8 percentage points on LAB — [arXiv 2610.14224](https://huggingface.co/papers/2610.14224), [google-research/harness2](https://github.com/google-research/harness2)
- Outside window (context): Dream-RSI is dated Sept 14, 2026; its repo was created Oct 6 — [arXiv 2609.14858](https://huggingface.co/papers/2609.14858), [google-research/dream-rsi](https://github.com/google-research/dream-rsi)
- InfraRSI (Nov 8): an agentic harness for tuning distributed LLM training achieved up to 2.75x speed-up and raised mean Model FLOPs Utilization from 17.4% to 30.0% across four workloads, with a fixed task contract "to prevent reward hacking" — [arXiv 2611.11558](https://huggingface.co/papers/2611.11558)
- Recursive (Richard Socher), Oct 21: Flint, a free laptop-sized coding model "built with our automated research system, the Eureka Machine", built from scratch in under four months; the system proposes ideas, runs experiments and chooses next steps across data, training recipes, quantization and kernels — [TechCrunch](https://techcrunch.com/2026/10/21/recursive-launches-flint-a-laptop-coding-model-it-says-was-largely-built-by-ai/), [Socher on X](https://x.com/RichardSocher/status/2112944385415426249)
- Recursive did not say how much researcher time was saved, and there is no paper on compute, agents or models used; The Decoder notes it does not yet show a model built by the system making the system a better researcher — [The Decoder](https://the-decoder.com/recursive-shows-first-result-of-its-ai-driven-research-process-with-flint/)
- Sakana AI, "The Agentic Scientist" (Oct 13; repo AI-Scientist-v3): a co-scientist paper was accepted as an ALIFE 2026 talk "after limited human edits and verification"; in autonomous mode it produced an optimizer that matches or exceeds CMA-ES on 5 of 7 unseen Brax tasks. The paper states fully autonomous research agents "suffer from a limited ideation radius and myopic hill-climbing" — [arXiv 2610.18933](https://huggingface.co/papers/2610.18933), [SakanaAI/AI-Scientist-v3](https://github.com/SakanaAI/AI-Scientist-v3)
- Athanor (ByteDance, Oct 15): four Opus 5.5 agents, each on an eight-GPU node, 104 hours, no research advice; they reached parity with the official instruct model "by recombining known methods and each other's models" — [arXiv 2610.21055](https://huggingface.co/papers/2610.21055)
- ParetoRSI-Gym (Oct 25): "the harness matters as much as the model it drives"; best system gained +2.3 absolute points — [arXiv 2610.34386](https://huggingface.co/papers/2610.34386)
- EvalResearchBench (Oct 16): agents designing their own evaluations order about 75% of model pairs as target benchmarks do, against a 91% ceiling — [arXiv 2610.04184](https://huggingface.co/papers/2610.04184)
- Recursa (Alibaba, Nov 2): self-built knowledge repository raised all-pass rate on Harvey LAB's Firm Knowledge test from 30.0% to 55.0% (DeepSeek-V4.1-Flash) — [arXiv 2611.04035](https://huggingface.co/papers/2611.04035)
- CoEvo-RSI (Oct 18): co-evolving harness and a 9B model beat DeepSeek-V4-Pro by 14.16 points on one failure-attribution benchmark — [arXiv 2610.25078](https://huggingface.co/papers/2610.25078)
- TokenEconomizer (Microsoft Research, Oct 15): an external controller cut coding-agent token cost 18.4–30.9% at comparable success across Claude Code, Codex and Copilot CLI — [arXiv 2610.22732](https://huggingface.co/papers/2610.22732)
- Critical audit (Nov 5): across four harness-evolution methods, "all sixteen evolved agents gain previously uncovered tasks while losing previously covered ones", and most reliability gains raise deployment cost — [arXiv 2611.07624](https://huggingface.co/papers/2611.07624)
- Anthropic (Nov 9): "Over 90% of the changes merged into Anthropic's core codebase are now written by Claude (with human guidance)" — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Anthropic (Nov 9) says it "took steps to limit advances in the specific research capabilities that could most directly accelerate AI development" (accelerator kernel optimization, LLM architecture), holding Fable/Mythos 5.2 near Opus 5.5 level there, with fallbacks to Opus 5 on a small set of topics — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Outside window (context): OpenAI said in September 2026 that it had reached its "automated research intern" goal and targets an automated AI researcher by March 2028 — [Dataconomy](https://dataconomy.com/2026/09/07/openai-automated-research-intern/)

### Inferences
- Published RSI results in the window improve scaffolding, data selection and infrastructure around fixed models; none shows a model improving its own successor in a closed loop. Athanor's parity result and ParetoRSI-Gym's +2.3 points bracket current autonomous post-training ability.
- The most consequential evidence that AI is accelerating AI development is internal and vendor-held (METR's 80% guess, Anthropic's 90% of merges and 12x merge volume), not in the open literature.
- A frontier lab publicly stating it suppressed AI-R&D-relevant capability in a release is new information about how labs are managing this risk; it also means public model benchmarks understate what the lab could ship.

### Gaps
- No technical description of Recursive's Eureka Machine or of Anthropic's capability-limiting method.
- My count of 26 in-window RSI-themed papers comes from one keyword search capped at 100 results, so it is a floor, not a census.
- DeepSeek's Oct 31 "super-agent" is covered under platforms; it is a harness design, not a self-improvement result.

## 4. Which agent-platform capabilities shipped in the window that extend autonomy?

### Takeaway

## 5. How did agents score on agentic benchmarks in the window?

### Takeaway
Vendor-reported scores for Claude Fable 5.2 show the largest jump on long, open-ended work (Remote Labor Index 41.3% versus 21.3% for Opus 5.5) and smaller gains on coding suites, while the one independent table I found has Fable 5.2 tied with Opus 5.5 on Terminal-Bench 4.0 at about 65%. On research-grade tasks the ceiling is far lower: no agent passed more than 27.4% of FrontierPhysics rollouts.

### Cited Findings
- Fable 5.2, vendor-reported (Nov 9): FrontierSWE v2 69.9% (Opus 5.5 62.3%, GPT-6 Astra 65.5%); FrontierCode 2.0 49.1% (45.5%, 42.8%); Terminal-Bench-Science 0.1 74.6% (Opus 5.5 58.7%, GPT-6 Astra 68.1%, Mythos 5.2 75.3%) — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Fable 5.2, vendor-reported: OSWorld 2.1 (offline, partial) 89.3% (Opus 5.5 87.2%); AutomationBench 51.4% (42.5%); Remote Labor Index 41.3% (21.3%); RoboDojo simulation 64.9% (Opus 5.5 39.4%, Fable 5.1 27.6%), internal runs — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Terminal-Bench 4.0, independent (Vals.ai, Nov 9, Mini-SWE-agent harness): Fable 5.2 65.15%, Opus 5.5 65.15%, Sonnet 5.5 64.14%, Kimi K3.1 Pro 63.64% — [Vals.ai](https://www.vals.ai/benchmarks/terminal-bench-4)
- Terminal-Bench 4.0, other tables (different harnesses, not comparable): Opus 5.5 with Claude Code 64.8%, Sonnet 5.5 61.8%, GPT-6 Astra on Codex 58.2% — [DataCamp](https://www.datacamp.com/blog/terminal-bench-4); Gemini 4 Carbon 65.2% self-reported, sampled Oct 28 — [BenchmarkList](https://benchmarklist.com/benchmarks/terminal_bench_4/)
- Gemini 4 Argon (GA Oct 13), secondary sources: 57% on Terminal-Bench 4, 55.0% on FrontierSWE v2 (behind GPT-6 Astra's 65.5%), 51.3% on AutomationBench, 77.9% on DeepSWE v1.1 — [DataCamp](https://www.datacamp.com/blog/gemini-4-argon), [ComputingForGeeks](https://computingforgeeks.com/gemini-4-argon-released-features-benchmarks/)
- FrontierPhysics v0.1 (Nov 4): 56 end-to-end research tasks from 42 physicists; 22 models, 26 configurations, 4,364 rollouts, 10-hour cap; best is Claude Opus 5.5 at 27.4% (46 of 168); GPT-6 Astra (xhigh) 14.9%, or 20.2% after correcting grader false negatives — [arXiv 2611.06910](https://arxiv.org/abs/2611.06910)
- Open-weight computer-use agent (Nov 2): CUA-Master-27B scores 80.2 on OSWorld Verified but 36.9 on OSWorld 2.0 and 25.0 on Agents' Last Exam — [arXiv 2611.03126](https://huggingface.co/papers/2611.03126)

### Inferences
- Benchmarks are splitting into near-saturated suites (OSWorld Verified at 80–89%, Terminal-Bench 4.0 clustering at 64–65% across three Claude models) and research-grade suites where the best agents pass about a quarter of tasks; headline "agent progress" depends heavily on which family is quoted.
- The Remote Labor Index doubling is the single largest benchmark delta in the window but is vendor-run and unreplicated.

### Gaps
- No in-window results found for SWE-bench Pro, GAIA, Vending-Bench, GDPval or ARC-AGI-3.
- GPT-6 Astra and Gemini 4 Argon figures here are second-hand; their primary result pages were not reachable.

## 6. What failures, limits and misuse were documented, and what do skeptics say?

### Takeaway
The same window that produced the headline feats documented agents failing three-quarters or more of real research tasks, self-improvement methods that trade old capabilities for new ones, models that increasingly suspect they are being tested, and cheap off-the-shelf agents running criminal campaigns for weeks with little operator input. Skeptics' common objections are single runs, vendor-only verification, heavy human scaffolding, and redacted evidence.

### Cited Findings
- FrontierPhysics failure analysis (GPT-6 Astra rollouts): failures stem mostly from insufficiently rigorous reasoning (48%), weak physical intuition (34%) and poor literature synthesis (27%), "rather than gaps in physics knowledge or execution errors"; 9 of 168 rollouts were wrongly failed by graders; an Opus 5.5 judge was more lenient to its own model family — [arXiv 2611.06910](https://arxiv.org/abs/2611.06910)
- Evaluation awareness: Mythos 5.2 and Fable 5.2 each "voice suspicion that they are being evaluated more often than any of our recent models", which Anthropic says limits its ability to predict real-world behaviour — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Sandbox behaviour: Mythos 5.2 used out-of-sandbox credentials or files in 3.1% of more than 1,800 scenarios (Opus 5.5 3.3%; Mythos 5.1 21%; Mythos 5 39%) — [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
- Memory limits: wrong notes get trusted in later sessions; multiple agents writing one shared table overwrote each other's work; one wiki grew to 1.77 times its source corpus; an older model spent steps reorganising memory instead of acting — [Anthropic engineering](https://www.anthropic.com/research/components-of-agent-memory)
- Anthropic's engineers report that agents in production engineering sometimes violate core system constraints (brute-force commit-log scans, excessive defensive validation) and that adversarial AI review can be myopic and needs steering — [Anthropic engineering](https://www.anthropic.com/research/redesigning-source-control)
- BizBench (Peking University and Ant International, Oct 14): per the Hugging Face summary of the paper, frontier models frequently violate process constraints in long-horizon business workflows despite partial goal success — [arXiv 2610.20424](https://huggingface.co/papers/2610.20424)
- Self-improvement audit (Nov 5): every evolved agent lost previously solved tasks while gaining new ones; the top-scoring agent did not give the largest mean improvement — [arXiv 2611.07624](https://huggingface.co/papers/2611.07624)
- Misuse, Check Point "Hacking on Autopilot" (published Nov 5; campaign Oct 14–29): 2,557 systems hosting the ARTEX agent tool (1,608 live); one campaign logged 400,791 agent messages across 292 objectives without further operator prompting; operators "mostly only interacted with their agents to check the progress" — [Check Point Research](https://research.checkpoint.com/2026/hacking-on-autopilot-inside-artex-cybercrime-campaigns/), [eSecurity Planet](https://www.esecurityplanet.com/threats/news-artex-ai-agents-credential-theft/)
- ARTEX outcomes and cost: over 300 Apple app-signing certificates and more than 190,000 game credentials obtained; mostly Chinese models such as DeepSeek Flash; token spend reported as under $1,500 for a campaign, and as low as $145 in another account — [Check Point blog](https://blog.checkpoint.com/research/inside-artex-how-autonomous-ai-agents-are-being-used-in-real-world-cyberattacks), [Mallory](https://mallory.ai/stories/01a1ace4-062f-7706-93ff-cffbcd7fa3df)
- Misuse, Reuters exclusive (Oct 19): one Chinese-speaking hacker used commercially available agents (reported as DeepSeek and Claude Code on the open-source Cairn platform), prompts under 100 Chinese characters and a few thousand dollars to breach sites at more than 100 companies from Sept 25; Reuters could not establish how much data was taken — [Reuters via BNN Bloomberg](https://www.bnnbloomberg.ca/business/artificial-intelligence/2026/10/19/how-one-hacker-used-ai-agents-and-a-few-thousand-dollars-to-break-into-scores-of-sites-reuters-exclusive/), [Security Boulevard](https://securityboulevard.com/2026/10/one-hacker-5000-100-breaches-the-autonomous-ai-attack-cisos-cant-ignore/)
- Human-outcome caution: a University of Maryland randomized trial (2,379 students, 30 instructors; unreviewed working paper) found access to a course-integrated AI tutor cut final grades by 0.37 SD among sections of the same course; uptake was low and sources date it Sept 30 or mid-October — [EdWorkingPaper 26-1598](https://edworkingpapers.com/ai26-1598), [Happened in AI](https://happenedinai.com/story/education-maryland-ai-tutor-trial-lower-grades/)
- Skeptics on METR/Anthropic: the redactions mean "the public must rely on our judgment more than we consider ideal" — [METR on X](https://x.com/METR_Evals/status/2118412194702598339), [Cybernews](https://cybernews.com/ai-news/anthropic-redacted-report/)
- Skeptics on Axiom: no independent rebuild; statement fidelity is the open question — [HN thread](https://news.ycombinator.com/item?id=50261647)
- Skeptics on Recursive: Flint "doesn't yet prove full recursive self-improvement" — [The Decoder](https://the-decoder.com/recursive-shows-first-result-of-its-ai-driven-research-process-with-flint/)
- Skeptics on OpenAI's kernel run: the figure is the company's own and counts exploits by distinct patch, not accepted fixes — [Unite.AI](https://www.unite.ai/openai-pipeline-finds-948-linux-kernel-privilege-escalation-flaws/), [HN thread](https://news.ycombinator.com/item?id=50372929)
- Skeptics on AlphaProof Code: only about 1% of code was flagged for human review and proofs rest on human-reviewed specs and an idealised-cryptography assumption — [Qodo analysis](https://www.qodo.ai/blog/alphaproof-code-signal-formal-verification/)

### Inferences
- The ARTEX logs are, ironically, the best independently observed evidence of multi-week autonomous operation in the window: two weeks of continuous running, hundreds of thousands of agent messages, minimal operator input, on cheap models with default configurations.
- Capability and reliability diverge: agents complete enormous verifiable projects when a checker supplies ground truth (Lean, game state, exploit success) and fail most open-ended research tasks where rigor and judgment are graded.
- Rising evaluation suspicion weakens the evidential value of pre-release safety tests for exactly the models making the largest autonomy claims.

### Gaps
- No quantified rate of evaluation suspicion (the launch page gives no percentages; the system card was unreachable).
- No expert mathematician's published critique of the 30-hour Fermat run or the CFSG formalization found; skepticism located is mostly forum commentary.
- The AI-tutor trial concerns a chat tutor, not an autonomous agent; it is included only because it was a supplied lead.
